# Инструменты и расходы первого этапа

Проверено: 2026-10-05. Этап: каталог, поиск/фильтр, детали, patch notes и API с фиксированными данными.

| pnpm | Установка и фиксация зависимостей | Уже доступен pnpm 11.19.0. Обычный npm здесь не найден; для текущей работы используем pnpm. |
| TypeScript и типы Node.js | Проверка типов, сборка UI/API | Установим бесплатные зависимости в проект после подтверждения плана. |
| Playwright | API и браузерные проверки, отчёты | Установим библиотеку и её тестовые браузеры. Платная подписка на инструмент не требуется. |

| Редактор и браузер с DevTools | Просмотр исходников и ручная проверка | Достаточно текущей среды и доступного браузера. Дополнительный платный редактор не нужен. |
| Интернет и место на диске | Загрузка пакетов и тестовых браузеров | Понадобятся при установке. Размер загрузок зависит от выбранных версий; точный объём сейчас не измерен. |
| Codex и агенты | Разработка, независимые проверки и исправления | Используется текущая среда работы. Точная стоимость зависит от плана, модели и объёма; отдельный OpenAI API ключ приложению не нужен. |

Дополнительные покупки для технической реализации этого этапа не обязательны. Работа агентов не является обещанием неограниченного бесплатного использования: она расходует доступный лимит или оплачиваемый ресурс текущей среды. Увеличивать подписку заранее не требуется; необходимость зависит от фактического использования. См. [официальные условия использования и тарификации](https://learn.chatgpt.com/docs/pricing).

Для первого приложения не требуются домен, хостинг, VPS, Docker, платная БД, сторонний каталог игр, ключи игровых API, платные картинки или отдельный AI API. Данные будут синтетическими; локальный запуск позволит начать QA работу. Публикация демонстрации является отдельным будущим решением.

## Как начнётся работа

После подтверждения [плана реализации](../docs/superpowers/plans/2026-10-05-catalogue-first-slice.md):

1. Исполнитель создаст небольшой проект и зафиксирует точные версии зависимостей и lockfile.
2. Будут установлены зависимости и браузеры Playwright. Если среда потребует разрешение для загрузки, оно относится к установке программных зависимостей, а не покупке подписки.
3. Приложение будет запускаться локально одной документированной командой; API и интерфейс будут на одном адресе.
4. Проверки будут использовать собственные временные базы, чтобы не изменять обычную базу приложения.
5. Каждый завершённый шаг пройдёт независимый review и будет сохранён коммитом в `main`.

Команды запуска приложения ещё не проверены: самого приложения пока нет. Будущий README должен включать только фактически проверенные инструкции.

## Что с GitHub Actions

CI полезен для портфолио, но его настройка не включена в этот первый срез. Сначала получим локально работающие проверки.

По текущим [правилам GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions), стандартные GitHub-hosted runners бесплатны для публичных репозиториев. Для приватных репозиториев предусмотрены лимиты; GitHub Free включает 2 000 минут в месяц и 500 MB хранения артефактов. Платные larger runners имеют отдельные условия. Для небольшой будущей проверки достаточно начать со стандартного Linux runner и короткого хранения отчётов.

Этот документ не утверждает, что репозиторий публичный, не меняет платёжные настройки и не включает оплачиваемые ресурсы.

## Ветки и сохранение первоначального плана

Документация перенесена в локальный `main` через fast-forward: перенесены все существующие коммиты без переписывания истории. Ветка `documentation` сохранена. Первоначальный план доступен в коммите `2d8761e`, поэтому его можно восстановить даже при дальнейшей работе в `main`.

Первый этап выполняется в текущей папке и в `main`, как выбрал пользователь. Новая worktree или отдельная ветка не создаётся. Публикация локальных изменений в `origin/main` не выполнена этим подготовительным этапом.

## Как устроен выбранный процесс агентов

Для каждой из трёх задач:

1. Координатор передаёт исполнителю с чистым контекстом отдельное задание, нужные интерфейсы и ограничения.
2. Исполнитель пишет проверку, фиксирует ожидаемую неудачу до реализации, реализует поведение, проверяет результат и сохраняет коммит.
3. Новый проверяющий читает задание, отчёт и весь diff задачи. Он даёт отдельные вердикты по требованиям и качеству.
4. Существенные замечания возвращаются исходному исполнителю.
5. Новый проверяющий оценивает исправления и отсутствие новых поломок в изменённом коде.
6. Следующая задача начинается после закрытия существенных замечаний. Незначительные замечания фиксируются и передаются в общий review.
7. В конце отдельный агент проверяет весь диапазон коммитов первого этапа, включая взаимодействие компонентов.

Без исправлений это три исполнителя, три проверяющих и один финальный проверяющий; координатор ведёт всю работу в текущем чате. Новые агенты не являются новыми пользовательскими чатами или покупаемыми аккаунтами. Исполнители не запускают собственных помощников. Одновременно несколько исполнителей одни и те же файлы не редактируют.

«Маленький агент» означает ограниченное задание и контекст. Это не гарантия меньшей стоимости каждого запуска. Для обычных задач выбирается подходящая модель, а глубокий общий review выполняется отдельно. См. [официальное описание subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).
