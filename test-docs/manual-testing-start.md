# Как начать ручное тестирование Game Companion

Это инструкция для самостоятельной сессии. Она не является отчётом о выполненных проверках.

## 1. Запуск в PowerShell

Открой PowerShell и выполни команды ниже. На этой машине Node.js и pnpm доступны из встроенного runtime Codex, но обычный Windows PowerShell может не видеть их. Первые строки добавляют существующие инструменты в PATH только текущего терминала. Затем команды создадут новую отдельную SQLite-базу для этой сессии; при первом запуске приложение заполнит её fixture version 1.

```powershell
Set-Location 'D:\Projects\WEB_DEV\WEB-DEV-QA-Portfolio'
$runtimeDependencies = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies'
$env:Path = "$runtimeDependencies\node\bin;$runtimeDependencies\bin\fallback;$env:Path"
$manualTestDirectory = Join-Path (Get-Location).Path ('test-results\manual-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Force -Path $manualTestDirectory | Out-Null
[IO.File]::WriteAllText((Join-Path $manualTestDirectory '.game-companion-test-owner'), "game-companion-test-database-v1`n")
$env:DB_PATH = Join-Path $manualTestDirectory 'games.sqlite'
$env:PORT = '3000'
pnpm dev
```

Держи этот терминал открытым. В конце сборки сервер напечатает адрес:

```text
{"url":"http://127.0.0.1:3000"}
```

Открой этот адрес в установленном Firefox. Если порт занят (`EADDRINUSE`), выполни `$env:PORT = '3001'`, затем `pnpm dev` и используй напечатанный адрес.

В этом рабочем каталоге зависимости уже установлены. Если ты уже создал тестовую базу, но получил «pnpm is not recognized», выполни в том же терминале только две строки с `$runtimeDependencies` и `$env:Path`, затем снова `pnpm dev`. Настройки DB_PATH и PORT сохранятся. Права администратора для этого не требуются; постоянные настройки PATH не меняются.

Этот путь встроенного runtime относится к текущей машине. Для нового клона нужны доступные из терминала Node.js версии, указанной в [package.json](../package.json), pnpm и `pnpm install --frozen-lockfile` перед запуском. Доступность можно проверить через `node --version` и `pnpm --version`. Дополнительный сервер базы данных или платная подписка не нужны.

Остановка сервера: **Ctrl+C** в терминале. `pnpm dev` собирает проект один раз; после изменений исходников останови его и запусти снова.

## 2. Подготовка заметок

Скопируй [шаблон сессии](manual-testing-session-template.md) в отдельный файл, например `manual-session-2026-10-09.md`. Заполни имя, фактическую дату, браузер и версию, адрес, размеры окна и путь базы. Не ставь Passed заранее.

Чтобы записать commit и состояние исходников, открой второй PowerShell в корне проекта:

```powershell
git rev-parse HEAD
git status --short
```

Текущая рабочая копия содержит незакоммиченные изменения. Одного SHA недостаточно для точного описания версии: запиши также это обстоятельство и сохрани вывод статуса.

В терминале с сервером после его остановки путь базы можно посмотреть через `$env:DB_PATH`. До остановки используй значение, назначенное командой запуска, или путь внутри созданного `test-results/manual-...` каталога.

## 3. Первые простые проверки: 15–20 минут

Полные процедуры и все обязательные варианты находятся в [test-scenarios.md](test-scenarios.md). Таблица ниже — удобные стартовые варианты для текущего фрагмента. Выполнение одного варианта не означает прохождение всего SCN.

| Сценарий / стартовый вариант | Действие | Ожидаемый результат |
| --- | --- | --- |
| SCN-CAT-01 / обычная загрузка | Открыть каталог на новой базе | 10 игр и корректный счётчик. Названия и жанры совпадают с [seed.ts](../app/db/seed.ts). Проверка удержанной загрузки остаётся отдельным вариантом. |
| SCN-CAT-02 / поиск | Ввести `Ember` | `Ember Trail` (ID 5) и `Ember Quest` (ID 6), всего 2. |
| SCN-CAT-02 / поиск + жанр | При `Ember` выбрать `RPG` | Только `Ember Quest` (ID 6), всего 1. |
| SCN-CAT-02 / отсутствие совпадений | Ввести `zzzzzz` | `No games found`; очистка фильтров возвращает 10 игр. |
| SCN-DET-01 / детали и заметки | Открыть `Orbit` (ID 1), затем `Patch notes` | Детали соответствуют ID 1. Версии заметок: `1.1.1`, `1.1.0`, `1.0.0` именно в этом порядке. Back возвращает в каталог. |
| SCN-DET-01 / пустые заметки | Открыть `Moss Garden` (ID 9), затем заметки | Явное сообщение об отсутствии заметок. Ответ `/api/games/9/patch-notes` — HTTP 200 и пустой `patchNotes`. |
| SCN-A11Y-01 / базовая клавиатура | Пройти поиск, жанр, ссылки игр, заметки и Back с помощью Tab / Shift+Tab / Enter и клавиш выбора | Видимый фокус, понятный порядок, управление доступно. Остальные варианты полного сценария остаются отдельными проверками. |

Избранное доступно по маршруту `/#/favourites`, форма обратной связи — по `/#/feedback`. Выполни полные процедуры [SCN-FAV-01](test-scenarios.md#scn-fav-01--toggle-and-reload) и [SCN-FAV-02](test-scenarios.md#scn-fav-02--storage-recovery-and-catalogue-validation), а также [SCN-FBK-01](test-scenarios.md#scn-fbk-01--required-fields), [SCN-FBK-02](test-scenarios.md#scn-fbk-02--named-email-variants-and-description-boundaries) и [SCN-FBK-03](test-scenarios.md#scn-fbk-03--successful-storage-and-failure-preservation). Записывай фактические результаты каждого варианта; не отмечай непроверенные варианты как Passed. Проверяй и отмечай отдельно только реализованные части составных сценариев доступности и адаптивности.

Для каждого выполненного варианта запиши точные действия, входные данные, ожидаемый и фактический результат, статус и ссылку на доказательство. Passed означает совпадение наблюдения с ожиданием; Failed — установленное несовпадение; Blocked — препятствие выполнению. Невыполненный вариант остаётся невыполненным.

## 4. Исследовательская сессия: 45 минут

Предлагаемая цель, которую можно уточнить по своим наблюдениям:

> Исследовать поиск, фильтры и переходы каталог → детали → заметки в Firefox, используя разные строки поиска, быстрые изменения настроек поиска, перезагрузку и историю браузера, чтобы выяснить, теряется ли актуальное состояние и остаётся ли интерфейс понятным при прерванных действиях.

Начни с этих идей, затем следуй интересным наблюдениям:

- Быстро менять `Ember` → `Orbit` → пустая строка и жанры. Сопоставлять актуальные поля и результаты.
- Добавлять пробелы по краям строки; пробовать ASCII-регистр `orbit` / `ORBIT`.
- Вставлять граничные строки длиной 80 и 81 символ. Для 81 ожидается валидация, отсутствие нового запроса и сохранение ранее загруженных результатов.
- Переходить в детали, возвращаться Back, пользоваться историей браузера, перезагружать детали по прямому адресу `/#/games/1`.
- Повторить интересную последовательность клавиатурой и при узком окне. Изменение окна — проверка viewport, не физического телефона.

Открой DevTools через F12. В Network смотри URL, параметры, порядок запросов, HTTP-статус и response; в Console сохраняй появившиеся сообщения. Записывай наблюдения по ходу сессии с временем и метками NOTE / QUESTION / RISK / BUG / IDEA. В конце выдели 5–10 минут на выводы: что проверено, что осталось, что требует отдельного расследования.

Для замедления, удержания и перестановки конкретных ответов нужны явно настроенные условия. Быстрый ввод сам по себе не доказывает выполнение всех вариантов SCN-CAT-05. Не отмечай их Passed без подтверждения порядка запросов и ответов. Аналогично, HTTP 500 и сетевые обрывы из полного плана требуют отдельной сессии с записанным способом моделирования; обозначай такие условия как SIM.

## 5. Отдельное наблюдение Firefox

В [автоматическом прогоне 2026-10-06](firefox-regression-results-2026-10-06.md) записано OBS-FF-01: `Script terminated by timeout` при завершении страниц. Его причина пока не установлена.

Обычный установленный Firefox и пакет Firefox для Playwright — разные среды. Запиши фактическую версию своего браузера. При отдельном исследовании перезагружай каталог и детали, уходи на другую страницу, наблюдай восстановление интерфейса и сообщения Console; при необходимости включи сохранение сообщений между переходами. Закрытие вкладки может уничтожить её DevTools, поэтому заранее сохраняй доказательства.

Если сообщение появилось, сохрани полный текст и стек, точную последовательность, частоту повторения и наблюдаемый эффект на интерфейс. Если не появилось, запиши «не воспроизведено в указанной среде». Это не устанавливает причину и не закрывает автоматически исходное наблюдение. Подтверждённый дефект должен иметь воспроизводимые шаги и обоснованное ожидаемое/фактическое поведение; предупреждение сначала можно оставить как NOTE / RISK.

## 6. Сохранение результатов и TestRail

Сохрани заполненный журнал рядом с QA-документами и положи выбранные скриншоты/логи в каталог доказательств с понятными именами. Используй исходные SCN / REQ IDs; не придумывай дефекты ради отчёта.

В [TestRail Game Companion (P3), suite 10](https://deepward.testrail.io/index.php?/suites/view/10) используй ручные SCN-кейсы. Для запуска выбери относящиеся к текущему фрагменту cases и укажи среду/объём. Результат всего case ставь Passed только после всех его обязательных вариантов; частичное исполнение подробно перечисляй в комментарии, сохраняя невыполненные варианты. Результаты не публикуются автоматически из локальных документов.

Если нужен повтор с исходными данными, сначала останови сервер и в **том же терминале**, где назначен DB_PATH, выполни:

```powershell
pnpm reset:test-db
pnpm dev
```

Это сбросит только назначенную отдельную тестовую базу. После завершения и остановки сервера можно очистить настройки этого терминала:

```powershell
Remove-Item Env:DB_PATH -ErrorAction SilentlyContinue
Remove-Item Env:PORT -ErrorAction SilentlyContinue
```
