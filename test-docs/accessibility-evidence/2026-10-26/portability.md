`source-manifest.json` records **retrospective Windows worktree byte hashes**, not canonical Git source hashes or contemporaneous hashes from the original scan. Of its 11 tracked source/config/test files, the initial index matched 10 exact hashes; `tests/accessibility/axe.spec.ts` differed only because its CRLF worktree source becomes LF in the Git blob. Its recorded raw SHA-256 is `f991deed9432ec2e0c8af3bd04dfb18325b70bc57cdd6694c8db73441f215a34`; the LF staged-source SHA-256 is `87527f01f72942e443cbdeab210e267925fb6d03e8d8e8d2ace4f60c20883225`. A fresh build may differ in line endings without implying a behavioral change. Do not use these raw worktree hashes as a cross-platform clean-checkout equality gate, and do not reinterpret them as hashes captured during the original axe run.

The scoped attribute protects evidence only; it does not impose a new source-format policy. Original report JSON still carries corrected rendered HTML/contrast evidence, and the recorded focused follow-up used freshly built source. No browser/tests were rerun for this byte-preservation check.
